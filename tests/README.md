# Тесты интерфейса

Два скрипта на Playwright. Оба гоняют приложение в демо-режиме (без Supabase),
поэтому ничего не трогают в базе и не требуют доступа к серверу.

## Подготовка (один раз)

```bash
npm install playwright-core           # без браузеров
# бинарь Chromium указывается переменной PW_CHROME, если он не в стандартном месте
```

## Запуск

```bash
# демо-копия: те же файлы, но пустой config.js — приложение стартует на localStorage
rm -rf /tmp/tlrun && cp -r . /tmp/tlrun
echo 'window.TECHLOG_CONFIG = {};' > /tmp/tlrun/config.js
(cd /tmp/tlrun && python3 -m http.server 8099 &) && sleep 2

node tests/ui-check.js 8099            # интерфейс + прокрутка, все экраны
node tests/repairs.js 8099             # документ ремонтных работ: сквозной сценарий
node tests/repairs-roles.js 8099       # он же: права работника, менеджера, админа
node tests/scroll-regress.js 8099      # перенос карточек, доска, режимы
node tests/stock.js 8099               # склад: регистр, большие кнопки, все операции
node tests/ui-matrix.js 8099 --shots   # 24 устройства: телефоны, планшеты, мониторы
node tests/tv.js 8099                  # режим телевизора: вход → экран ТВ, киоск, настройки и конструктор (v1.08.37)
node tests/v1_08_38.js 8099            # офлайн-режим (пилюля связи, блеклые серверные кнопки, задача без сети) и спойлеры инвойса
node tests/v1_08_39.js 8099            # бухгалтерия: роль, реестр, проценты, отметки, CSV, сводка по сотрудникам (v1.08.39)

node tests/unit.js                     # jsdom, без браузера: словарь, версии, регистр-математика
```

```bash
# БД (одна транзакция, в конце ROLLBACK — безопасно для любой базы):
psql "$DB_URL" -v ON_ERROR_STOP=1 -f tests/acc.sql   # бухгалтерия: роль, acc_doc_mark, триггер acc_guard, acc_settings, RLS (v1.08.39)
```

## `v1_08_39.js` и `acc.sql` — бухгалтерия (v1.08.39)

`v1_08_39.js` (демо, 50 проверок): вход бухгалтером — свой набор вкладок без
главной/доски/склада и бейдж роли; реестр раскладывает демо-инвойс по
категориям (клининг $295, аренда $630 = BLW $450 + DHM $180, итог $925 =
jobGrand), проценты сохраняются одной кнопкой (общий процент аренды и свой
на BLW → «К выплате» $226, название колонки, штамп автора, отказ для 140 %),
карта «секция → категория» (Other services → материалы и сброс), отметка с
заметкой и массовая отметка, фильтры и поиск, карточка только для чтения
вместо формы, сводка по сотрудникам (поровну ↔ основному), CSV (BOM, шапка,
итог), у админа — вкладка и строка «Бухгалтерия» в форме инвойса, у техника
вкладки нет и бухгалтера нет в выборе исполнителя; ПК-таблица на 10 колонок;
словарь ru/en.

`acc.sql` (43 проверки): роль accountant в constraint / admin_set_role /
admin_create_user, RPC `acc_doc_mark` для бухгалтера и админа (техник и
менеджер — FORBIDDEN; BAD_STATUS, BAD_KIND, NOT_FOUND, NOTE_TOO_LONG),
триггер `acc_guard` (чужой upsert полной строки отметку не затирает, апрув
не сбрасывается, пуш не уходит), `acc_settings` (штамп автора, 0…100,
восстановление через `admin_restore_rows`), RLS под `authenticated`
(бухгалтер читает чужие документы и пишет acc_settings, техник и менеджер
настроек не видят).

## `stock.js` — склад и регистр оборудования (v1.08.29)

Сквозной сценарий на экране «Склад» в демо-режиме (движения аренды в демо
зеркалит `demoPlMoves` — та же логика, что у серверного триггера): начальный
ввод → аренда с **авто-добором** → большие кнопки «Взять/Сдать» (чипы типов,
кнопка «всё · N», степпер, счётчики) → ремонт туда-обратно → поступление с
комментарием и списание (админ) → «забрал» → «Вернуть всё на склад» → отмена
вывоза → правка количества аренды → **бумажное** частичное продление →
справка «?» со схемой → экран техника без админских кнопок. ~36 проверок.

## `stock-register.sql` — сквозной автотест базы (все типы документов)

Не Playwright: чистый SQL по-настоящему выполняется в базе со схемой
v1.08.27+ и создаёт **все типы документов приложения** — пропозал, работу
(связь `link_job_proposal`), аренды двух типов оборудования, запросы
продления (отклонение и одобрение через `decide_ext_request` — полное и
частичное), «забрал»/«вернул» с отменами, правку количества, документ
ремонтных работ с апрувом, заявку на код доступа, все семь операций регистра
и удаление работы с каскадом, плюс блок **«профили и роли»**: создание
сотрудника админом, назначение всех трёх ролей, блокировка/разблокировка,
правка профиля и регрессия бага «админ не может изменить роль»
(клиентский RLS-upsert). После каждого шага сверяются остатки
(`equip_bal`, `stock_counts`), в конце — инвариант сохранения журнала и
счётчик аудита. **Безопасен для любой базы**: одна транзакция, в конце
`ROLLBACK` — не остаётся ни строки, даже в `audit_log`.

```bash
psql "$DB_URL" -v ON_ERROR_STOP=1 -f tests/stock-register.sql
psql "$DB_URL" -v ON_ERROR_STOP=1 -f tests/tv.sql   # v1.08.37: сессии ТВ, апрув, фид, отзыв (BEGIN…ROLLBACK)
```

Или вставьте файл целиком в Supabase SQL Editor: строки `ok …` появятся в
выводе, успех — `СКЛАД-РЕГИСТР: все N проверок пройдены`. Любое расхождение
останавливает скрипт ошибкой с именем шага.

Сервер должен подниматься **в том же вызове оболочки**, что и тест: фоновые
процессы между вызовами не переживают.

## `ui-check.js` — интерфейс и прокрутка

Дергает тот же движок, что и кнопка «Диагностика интерфейса» в приложении
(`window.UIDiag`), по всем экранам и в двух режимах — телефон 414×896 и ПК
1440×900. Валит сборку, если:

* появился **блокирующий** (не `passive`) слушатель `wheel` / `touchmove`
  на `window` или `document` — из-за таких прокрутка ждёт главный поток
  на каждом экране приложения. В отчёте печатается файл и строка, где
  слушатель зарегистрирован;
* сработала любая «жёсткая» проверка: перекрытие интерактивных элементов,
  налезание соседних блоков, вылет за правый край, кнопки, недоступные под
  панелями, битые `onclick="App.xxx()"`, дубли `id`, просадки кадров.

Замечания об оформлении (контраст, размер зон нажатия, обрезанный текст)
печатаются, но сборку не валят — они в списке `SOFT`. Чтобы валили тоже:

```bash
UI_STRICT=1 node tests/ui-check.js 8099
```

## `scroll-regress.js` — что могло сломаться от правок прокрутки

С v1.07.67 `wheel` вешается на сам `.board` при отрисовке, а `touchmove` —
на перетаскиваемые карточки главной. Тест сторожит именно эти места:
привязку обработчиков после `render()`, перенос карточки пальцем через
long-press, горизонтальную прокрутку доски колесом и уборку ПК-надстроек
при возврате в мобильный режим.

## `ui-matrix.js` — разные экраны и разрешения

Открывает приложение в размерах настоящих устройств и на каждом обходит все
экраны тем же движком. Набор: iPhone SE / 13 mini / 14 / 16 Pro / 15 Plus /
16 Pro Max, узкий Android 360, Pixel 7, минимальные 320px, iPhone в альбомной,
iPad mini / 10.9 / Pro 12.9 книжной и альбомной, ноутбуки 1280 и 1366,
MacBook 1440, Full HD, 2K и ultrawide 3440 — в обоих режимах приложения там,
где это имеет смысл.

Итог складывается в `tests/out/`:

* `ui-matrix.md` — читаемый отчёт. Замечания сгруппированы **по сути**, а не по
  устройству: одна и та же беда на восьми телефонах — это одна запись со
  списком устройств, а не восемь одинаковых абзацев;
* `ui-matrix.json` — то же машинно, удобно сравнивать выпуски;
* `shots/*.png` — снимки главной, доски и настроек на каждом устройстве
  (только с ключом `--shots`).

Полезные ключи:

```bash
node tests/ui-matrix.js 8099 --only=iPhone,iPad     # часть набора
node tests/ui-matrix.js 8099 --screens=home,settings # часть экранов
```

Чего эмулятор **не** покажет: вырез и домашнюю полосу iPhone
(`env(safe-area-inset-*)` там всегда 0), настоящую инерцию прокрутки iOS и
системный масштаб шрифта. Это проверяет кнопка диагностики на живом
устройстве — она пишет в отчёт размер экрана, плотность точек, ориентацию,
безопасные поля и режим, так что присланный `.txt` читается однозначно.

## Порог

Если понадобится править движок проверок — он весь в `uidiag.js`, в одном
файле с кнопкой и отчётом. Тесты новых проверок не требуют: они читают
`window.UIDiag.json()` и ориентируются на уровень (`err` / `warn` / `ok`).


## unit.js — логика без браузера (v1.08.08)
`npm i jsdom@24` и `node tests/unit.js`. 216 проверок за ~3 секунды: словарь ru/en,
нумерация документов, двуязычные заметки и транслит, права на перевод, архив,
съёмка, контракты edge-функций и SQL-файлов. Браузер не нужен.

## offline.js — обрывы связи (v1.08.08)
`node tests/offline.js <порт>` при поднятом сервере. Проверяет запуск без сети из
кэша service worker, переходы по экранам в офлайне, сохранность правки после
перезагрузки без сети, доступность очереди фото и возврат сети.

## chain.js — цепочка документов (v1.08.11)
`node tests/chain.js <порт>` при поднятом сервере. Строит сценарии полного и
частичного продления, проверяет вызов цепочки из работы и из пропозала,
порядок карточек, метки «вы здесь» и «закрыт продлением», дни на стрелках и
переключение линии с горизонтальной на вертикальную.

- `v1_08_38.js` — офлайн-режим и спойлеры инвойса: пилюля связи под логотипом (зелёная «NN мс» → красная «офлайн» при `context.setOffline(true)`), пометка серверных кнопок `.net-need`, перехват клика подсказкой без вызова обработчика, создание задачи без сети, возврат сети снимает блокировку; форма работы — пустые секции свёрнуты, тап по заголовку, «?» не сворачивает, «Развернуть все (N)» ↔ «Свернуть пустые», ручной выбор переживает перерисовку, ПК-бланк с подписью DESCRIPTION. Демо-режим, ~43 проверки.
- `unit.js` с v1.08.38 дополнительно поднимает второй jsdom **в режиме Supabase на заглушке клиента** и проверяет офлайн-запись: без сервера `dbUpsert`/`dbDelete`/`dbSaveOrg`/`audit` не делают ни одного вызова и кладут строки в `techlog_pending` (включая `insert` журнала и `org_settings`), `pendingFlush` досылает всё одним проходом, сетевая ошибка «на ходу» оставляет запись в очереди.
- `v1_08_33.js` и `bouncie.js` читают Leaflet-заглушку из `/tmp/pw/leaflet-stub.js` (в репозиторий не входит): она должна не только отдавать цепочечные no-op (`L.map().attributionControl.setPrefix`, `L.control.attribution()`), но и **рисовать маркеры в DOM** контейнера карты — `<div class="pw-marker" data-pop="…">{divIcon.html}</div>` и `<div class="pw-line dash">` для полилиний с `dashArray`, иначе проверки карты Bouncie падают на `.map-car`.
- `v1_08_33.js` — пуши/2FA в настройках, глобальный поиск (свои активны, чужие «замком»), отчёт «Время», оптимизация маршрута, «Создать такую же», ⚙-доступы и сессии в Штате, значки машин (Check Engine / ТО / трек). Демо-режим, порт как у остальных.
- `v1_08_39.js` — бухгалтерия: роль «Бухгалтер» (свои вкладки, редирект главной, бейдж, форма инвойса не открывается — карточка только для чтения), реестр (раскладка демо-инвойса $295 / $630 с BLW $450 · DHM $180 / $925), проценты (общий процент аренды + свой на BLW → «К выплате» $226, отклонение 140 %), карта «секция → категория» и сброс, отметки и заметка бухгалтера (одиночная, массовая, фильтры), поиск, сводка по сотрудникам (поровну / всё основному), CSV с BOM, вкладка у админа и её отсутствие у техника, бухгалтер вне выбора исполнителя, ПК-таблица на 10 колонок, полнота словаря acc_*. Демо-режим, ~50 проверок.
- `acc.sql` — сквозной сценарий бухгалтерии на живой базе (BEGIN…ROLLBACK, схема v1.08.39): роль accountant в constraint / `admin_set_role` / `admin_create_user`, `acc_doc_mark` (бухгалтер и админ ставят отметки на инвойс и REP; техник и менеджер — FORBIDDEN; BAD_STATUS / BAD_KIND / NOT_FOUND / NOTE_TOO_LONG), триггер `acc_guard` (полная строка техника учётные поля не затирает, апрув не сбрасывается, пуши не уходят), `acc_settings` (штамп автора, check 0…100, восстановление через `admin_restore_rows`), RLS под ролью `authenticated` (бухгалтер читает чужие документы и пишет `acc_settings`, чужой инвойс не пишет; техник и менеджер `acc_settings` не видят). Запуск: `psql "$DB_URL" -v ON_ERROR_STOP=1 -f tests/acc.sql`, ~43 проверки.
- `unit.js` с v1.08.39 проверяет раскладку по категориям (`accSplitJob` / `accSplitRep`), проценты и переопределение по типу техники, пропорцию при апруве, доп. работы (покупка → материалы, флаг «ремонт» → ремонт, карта extra), реестр с REP, итоги и сводку по сотрудникам, фильтры и `viewAcc`.
