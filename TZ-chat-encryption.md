# TechLog · шифрование переписки: как это сделать

Продуманная схема по требованиям от 21.09.2026: общий чат, личные чаты, группы; ключ хранится на
устройстве; переписку можно восстановить, если есть доступ хотя бы к одному устройству; два режима —
«с восстановлением» (по умолчанию) и «полное шифрование» (с предупреждением и повторным вводом пароля);
при включении шифруется и старая переписка, при отключении — всё расшифровывается.

Группы сделаны в v1.09.20 — шифрование обязано покрывать их с первого дня, поэтому они идут раньше.

## 1. Три уровня ключей

Используется только встроенная в браузер криптография (WebCrypto). Свой протокол не изобретаем.

| Ключ | Что это | Где живёт |
|---|---|---|
| **Личный ключ сотрудника** (пара ECDH P-256) | «удостоверение»: на его открытую половину другим можно запирать ключи переписок | закрытая половина — на устройстве; копия в «сейфе» на сервере (см. §2) |
| **Ключ переписки** (AES-256-GCM, случайный) | один на каждую переписку: личную, группу, общий чат. Им шифруются текст, цитата, миниатюра, снимок | на сервере лежит отдельно запертым для каждого участника — его открытым ключом |
| **Ключ из пароля** (PBKDF2-SHA-256, 600 000 итераций, своя соль) | им запирается «сейф» с личным ключом | нигде не хранится: вычисляется из пароля в момент входа |

Одна схема на все виды переписок — главное упрощение. Личный чат — это «группа из двоих».
Добавили человека в группу — любой участник запирает для него ключ переписки, и новичок видит всю
историю. Убрали человека — ключ переписки меняется, новые сообщения он не прочтёт.

В базе остаются открытыми только служебные поля: кто, кому, когда, id приложенного документа,
реакции. Текст, название документа, миниатюра и сам снимок — шифротекст.

## 2. Два режима — это два способа хранить личный ключ

Сообщение принадлежит всем участникам переписки, поэтому «режим» — свойство не сообщения, а того,
**где лежат копии личного ключа сотрудника**. Каждый выбирает режим сам.

| Ситуация | С восстановлением (по умолчанию) | Полное шифрование |
|---|---|---|
| Новое устройство, пароль помню | история видна | история видна |
| Пароль забыл, но есть вошедшее устройство | устройство перезапирает сейф новым паролем | то же самое |
| Пароль забыл, устройств нет | админ сбрасывает пароль — история возвращается | **история потеряна навсегда** |
| Может ли админ технически расшифровать | да (в приложении такой кнопки нет, но возможность существует) | нет |

Как это устроено:

- **На устройстве** личный ключ хранится в IndexedDB неизвлекаемым (скрипт может им пользоваться, но
  не может прочитать). Рядом лежит его копия, запертая ключом устройства, — она нужна, чтобы
  перезапереть сейф после смены пароля. При выходе из аккаунта оба стираются.
- **Сейф на сервере** (оба режима): личный ключ, запертый ключом из пароля. Вход на новом устройстве:
  логин + пароль → сейф открылся → вся история. Сотрудник ничего нового не замечает.
- **Второй замок — только в режиме «с восстановлением»**: тот же личный ключ, запертый ключом
  восстановления фирмы (он есть у админов). Забыл пароль → админ сбрасывает его как сейчас, приложение
  админа перезапирает сейф временным паролем.
- **Полное шифрование** = второй замок удаляется. Включение: предупреждение красным, три пункта «что
  потеряю», поле повторного ввода пароля, кнопка активна только после верного пароля. Выключение —
  так же через пароль: второй замок создаётся заново.

Честная оговорка, которую увидит и пользователь: полное шифрование защищает **его ключ**. Если
собеседник в режиме «с восстановлением», их общую переписку технически можно открыть через ключ
собеседника. Поэтому в шапке переписки два значка: 🔒 «зашифровано» и 🔐 «полное» — второй только
когда в полном режиме **все** участники.

Смена пароля: сообщения не трогаются — перезапирается только сейф (одна запись).

## 3. Включение и отключение шифрования

Включать и выключать шифрование **как таковое** может только администратор и сразу для всей фирмы:
сообщение общее, один участник не может расшифровать его «для себя», не раскрыв собеседнику.
Личный выбор сотрудника — режим хранения ключа (§2).

- **Включили** → приложение каждого участника при ближайшем входе шифрует старые сообщения своих
  переписок пачками по 100 (функция принимает шифротекст только для ещё открытых строк — два
  устройства не помешают друг другу). В настройках админа — счётчик «осталось открытых: N».
- **Выключили** → так же, в обратную сторону: приложение участника расшифровывает и возвращает текст.
  Переписка, где есть участник в полном режиме, **не расшифровывается**, пока он сам не выйдет из
  этого режима: его выбор сильнее выключателя админа.
- Расшифровать без участников сервер не может — в этом и смысл. Поэтому обе операции идут «по мере
  захода людей», а не мгновенно.

## 4. Что изменится для людей

- Вход, смена пароля, чат — как сейчас. Один раз после обновления приложение спросит пароль
  («чтобы включить защиту переписки»): сессия уже открыта, а пароля в памяти нет.
- **Пуш**: сервер больше не знает текста. Сначала пуш будет «Новое сообщение от Ивана»; затем —
  расшифровка прямо на телефоне, и текст в пуше вернётся (не на всех устройствах это возможно).
- Новичок в общем чате видит старые сообщения не сразу, а когда любой коллега окажется в сети (его
  приложение само выдаст новичку ключ). До этого — «🔒 ждём ключ».
- Минимальная длина пароля станет 10 символов: при утечке базы стойкость защиты равна стойкости пароля.

## 5. Порядок работ — так, чтобы не потерять ни одного сообщения

1. **v1.09.20 — группы** (сделано). Без шифрования.
2. **Ключи без шифрования.** Личные ключи, сейф, ключ фирмы, оба режима, перезапирание при смене и
   сбросе пароля, экран «у кого ключи готовы». Сообщения ещё открытые. Если в ключах ошибка — мы
   увидим её на экране, и ни одно сообщение не пострадает. **Это главный предохранитель.**
3. **Шифрование новых сообщений и снимков**, значки 🔒/🔐, общий пуш без текста.
4. **Старая переписка**: шифрование при включении, расшифровка при выключении, счётчик у админа.
5. **Удобства**: текст в пуше (расшифровка на телефоне), перенос ключа на новое устройство по QR без
   пароля (для полного режима).

Каждый шаг — отдельный выпуск с тестами на двух браузерах; шаги 2–3 я прошу проверить на ваших
телефонах до того, как включать шифрование всем.

## 6. Чего эта схема не даёт — честно

- Нет «прямой секретности»: если личный ключ утёк, читается вся история с ним (у WhatsApp ключи
  меняются постоянно; вручную повторять протокол Signal рискованнее, чем его отсутствие).
- Веб-приложение получает свой код с хостинга: кто управляет хостингом, может подменить код. Это
  защита от утечки базы и от чтения таблиц, а не от владельца сервера.
- Не скрывается, кто с кем и когда переписывался.
- Поиск по переписке — только на устройстве.
